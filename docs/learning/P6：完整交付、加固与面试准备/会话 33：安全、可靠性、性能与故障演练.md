# 会话 33：安全、可靠性、性能与故障演练

## 结果与设计

本轮把安全负向测试、10k 性能基线、Prometheus 可观测性和依赖故障演练固化为独立入口。Work Item 列表改为摘要 DTO，避免读取和传输正文；两个分页复合索引分别服务无筛选和类型/状态筛选。

```text
浏览器 / 性能脚本
  -> forge-web 同源代理
  -> forge-server Session + CSRF + workspace/project 授权
  -> WorkItemMapper 覆盖索引分页
  -> MySQL 权威事实

Prometheus
  -> /actuator/prometheus
  -> HTTP/JVM Micrometer 指标
  -> ReliabilityMetricsMapper
  -> Outbox、索引任务与 Webhook 死信事实
```

Qdrant、Agent 和 GitLab 是可降级外部依赖；MySQL 和 Redis 是请求正确性所需依赖。前两类故障不得伪造成功，后两类故障必须令 readiness fail-closed。

## 数据与事务边界

- Work Item 性能数据使用固定 `PERF` 项目和幂等主键，10,000 条数据在单次 MySQL 事务中装载。
- 列表查询只读取摘要列，并始终携带 `workspace_id`、`project_id` 和 `deleted_at` scope；分页性能索引不削弱租户隔离。
- 可靠性 gauge 每次 scrape 只执行只读聚合 SQL，不更新重试状态，也不把派生指标写回业务库。
- Qdrant、Agent、GitLab 调用仍位于数据库行锁事务之外；错误只向调用方暴露稳定语义，不回显远端响应正文。

## 关键文件与代码

- `WorkItemSummary.java`：定义列表最小数据面，不包含正文和 reporter 字段。
- `WorkItemPage.java`：分页容器改为承载摘要，详情接口仍返回完整 Work Item。
- `WorkItemMapper.java`：列表 SQL 只选择页面所需列，保留明确的租户和项目条件。
- `MybatisWorkItemStore.java`：把分页结果映射为摘要，避免在应用层拿到不需要的正文。
- `V26__session33_performance_indexes.sql`：新增 scope 分页与筛选分页覆盖索引，不回改历史迁移。
- `work-item-api.ts`、`ux-workspace.tsx`：Web 类型和页面同步摘要契约，不再渲染列表正文。
- `QdrantVectorIndexClient.java`：远端失败消息只保留操作和状态码，阻断响应体中的 Secret 泄露。
- `ReliabilityMetricsMapper.java`：从 MySQL 聚合 Outbox backlog、最老年龄和两类死信。
- `ReliabilityMetrics.java`：注册四个 gauge；数据库采集失败时返回 `NaN` 而不是虚假的零。
- `application.yml`、`pom.xml`：启用 Prometheus registry、HTTP histogram 和 100ms 至 5s 的 SLO buckets。
- `check-secret-leaks.sh`、`secret-leak-scan.sh`：实现高置信泄密扫描及扫描器自身的正反测试。
- `test-session33-hardening.sh`：串联安全、权限、幂等、降级、指标和前端重放门禁。
- `session33-performance.sql`、`run-session33-performance.sh`：构造 10k 数据，验证执行计划并采集真实 API P95。
- `run-session33-fault-drills.sh`：逐个停止依赖，断言 fail-closed 或 degraded，并用退出钩子恢复。
- `session33-hardening.md`：给出人工运行顺序、风险提示、PromQL 和验收清单。

- `PrometheusEndpointTest`：验证 HTTP histogram buckets 和 JVM 指标可抓取。
- `ReliabilityMetricsTest`：验证四个业务 gauge，并验证数据库失败返回 `NaN`。
- `secret-leak-scan.sh`：安全样例通过、危险样例必须失败，且仓库扫描通过。
- 会话 33 Server 定向门禁：71 个测试通过，0 失败、0 错误、0 跳过。
- Work Item、请求传输和 SSE reducer：8 个 Web 测试文件、24 个测试通过；生产构建和 TypeScript 检查通过。

- 独立 Compose 故障演练：Qdrant/Agent 降级可用，Redis/MySQL readiness 返回 503，恢复后六个服务均健康。

## 风险与遗留项

- 高置信 Secret 正则有意控制误报，不能发现所有自定义凭据格式；生产仍需平台级 Secret 扫描和轮换。
- HTTP histogram 按标准化 URI 聚合；若框架产生高基数 URI 标签，需要在生产观测中继续审计。
- 性能脚本测量本机 Compose 端到端延迟，结果受宿主机负载影响，应保存机器规格和原始输出再比较趋势。
- 故障脚本会短暂停止本地依赖，因此本轮提供但不在可能被共用的开发环境中自动执行。
- GitLab 故障通过真实 HTTP stub 覆盖超时、401 和重定向；Compose 没有 GitLab 服务，故不伪造一个新部署拓扑。
- 本轮不实施会话 34 的发布、部署或阶段复盘内容。
