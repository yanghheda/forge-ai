# 会话 07：登录、Spring Session 与退出

## 我完成了什么

- 用户可用邮箱和本地密码登录，读取 `/api/v1/me`，并通过退出立即撤销当前 Redis Session。
- 登录成功轮换 Session ID；两个并发会话互不覆盖，退出其中一个不影响另一个。
- Redis 承担 Session 与短期限流；MySQL 保存用户状态、锁定计数、最近登录和追加式认证审计。

## 我理解的核心设计

- Cookie 只保存不透明 Session ID，认证主体保存在服务端，因此服务端删除 Session 后旧 Cookie 立即失效。
- `AuthenticationFilter` 只把有效 Session 转成请求级 `AuthContext`；`/me` 仍从 MySQL 读取当前有效 Workspace 和角色，不信任 Session 中的权限快照。
- BCrypt 校验在数据库写事务之外执行；成功/失败状态更新与对应审计在一个短事务内提交。
- 未知邮箱使用固定 dummy BCrypt 摘要，公开错误不区分未知用户、错误密码、禁用和锁定状态。
- 空闲过期由 Spring Session 执行，绝对过期由首次签发时间和认证 Filter 共同执行。

## 失败路径

- Redis 限流键使用客户端地址与规范化邮箱的摘要；超限返回稳定 429，并记录匿名失败审计。
- 第 5 次连续失败原子更新 MySQL 计数并锁定 15 分钟；锁定期间的请求不会继续延长锁定，避免外部攻击者永久锁死账户。
- Redis 不可用时 Session 与限流均 fail closed；MySQL 业务事实仍保留，但用户需要在 Redis 恢复后重新登录。
- Redis Session 被删除、空闲超时或达到绝对期限后，请求统一返回 401。

## 测试证据

- 真实 MySQL/Redis 集成测试覆盖正确/错误密码、未知用户、锁定、并发失败、限流、Session fixation、并发会话、logout、Redis 删除和绝对过期。
- Flyway 测试验证 V4 从空库迁移、审计空主体/空 Workspace 语义和历史迁移 checksum。
- 架构与 Java 成员注释测试继续阻止层次倒置、跨模块 Repository 访问及缺失中文普通块注释。

## 遗留边界

- CSRF Token、Origin 校验和 Web 登录闭环属于会话 08。
- 全会话撤销将在密码或权限敏感变更入口出现时接入；本轮只公开撤销当前 Session。
- Workspace/Project 管理和完整 RBAC 授权属于会话 09–10。

## 3 个复盘问题

1. 登录审计成功、但 Redis Session 写入失败时，产品层面是否需要区分“认证成功但会话创建失败”？ 不用区分吧，直接提示服务器不可用。内部必须区分，否则会出现审计记录显示“登录成功”，实际上用户并未获得会话。
2. 后续密码修改或管理员禁用用户时，应立即批量撤销全部 Session，还是允许已有 Session 在短暂窗口内继续存在？ 应立即撤销全部 session。主动删除全部 Session，加数据库版本校验兜底，才算真正的立即失效。
3. 当前限流维度是“远端地址 + 邮箱摘要”；面对共享出口 IP 和分布式撞库，是否还需要额外的纯 IP 或全局账号维度？ 需要。对外不区分，对内必须区分 Session 创建失败。密码安全事件和禁用操作应立即撤销全部 Session，并增加数据库版本兜底。需要纯 IP、纯账号及全局保护，但应使用不同阈值和动作，避免形成新的拒绝服务入口。
