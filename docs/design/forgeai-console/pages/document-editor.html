1 背景与目标

ForgeAI 面向 B 端私有化部署环境，帮助研发组织以 PRD 为事实来源，编排 Product、UX、Dev、QA、Release 五类智能体协同交付需求。为验证产品完整链路，并支撑售前演示与版本回归，需要交付一条可重复执行的「黄金 Demo」：以「增加手机号验证码登录」为固定样例需求（会话 32 固定样例），从 PRD 导入开始，历经 UX 设计、开发、QA 测试，最终完成一次 SIMULATED 模拟部署。

黄金 Demo 同时承担端到端回归基线职责：演示数据固定占用 32000–32999 ID 段，GitLab 与 LLM 使用确定性演示实现，不产生真实外部副作用；九类负向门禁必须全部被固定状态机 Guard、Tool 权限 allowlist 与发布预检拦截，且全过程可在执行轨迹中回放与审计。

目标

  • 端到端可重复：执行 make demo-seed 重置样例后一键跑通正向链路，30 分钟内演示至模拟部署完成。
  • 人机协同可验证：Agent 负责执行，合并 MR、发布部署等高风险动作必须人工审批，并支持人工接管与异常恢复。
  • 全程可观测：每次状态流转、评审结论与受控工具调用均产生 Trace 事件与不可删除的审计记录。

3 功能需求

3.1 PRD 导入与不可变版本

支持在需求详情中创建 PRD，Web 编辑器基于 Tiptap，内容以 ProseMirror JSON 保存，服务端同时生成规范化纯文本供搜索、摘要与内容哈希使用。

  • 每次显式保存生成单调递增的不可变版本；评审通过的版本只读不可修改，只能基于其创建新草稿。
  • 自动保存仅写入浏览器 LocalStorage 草稿（键含 userId/documentId/baseVersion）；发现服务端版本变化时提供「查看差异 / 复制草稿 / 丢弃」，不得静默覆盖。
  • 发布指定版本时，版本创建与 current_version_id 切换在同一事务完成；搜索索引异步构建，索引失败不影响发布事实。

3.2 Agent 审批与人工接管

Agent 通过受控 Tool API 调用 forge-server，不直接写业务数据库，不持有 GitLab Token 或部署凭据。合并 MR、部署等高风险工具默认要求人工审批，审批结论与动作同事务写入审计。

  • Tool manifest 采用 allowlist 与权限集合双重校验；Prompt Injection 诱导部署必须被拒绝，并在 Trace 中标记为越权尝试。
  • 审批发起后等待 30 分钟无人响应，任务自动转入待恢复状态并通知备份审批人；等待期间冻结该任务的后续调度，避免重复执行。
  • 人工可随时接管：接管后 Agent 停止自动执行，人的操作同样写入审计；接管结束后从服务端最新事实状态恢复，而非沿用本地缓存。

3.3 执行轨迹采集与回放

每次 Tool 调用按 run / step / tool 三级记录，可按需求聚合形成执行轨迹，支撑演示回放与问题定位。

  • 轨迹包含工具名、入参摘要、结果状态、耗时与幂等键；敏感字段脱敏后展示。
  • Webhook 重复投递与 Tool 重试依赖持久化幂等，轨迹中可识别重复事件且不触发二次状态推进。

4 非功能需求

  • 性能：单需求 1 万事件内，Trace 列表 P95 响应不超过 500ms；编辑器本地草稿自动保存无感知卡顿。
  • 权限与隔离：所有 Mapper 查询显式携带 workspace_id / project_id scope；Developer 对 PRD 只读，不能代替批准 Release。
  • 审计：状态流转、评审、审批与部署动作与业务变更同事务写事件，审计记录不可删除，保留期不少于 3 年。

5 验收标准

  1. make demo-seed 后以 owner@demo.forgeai.local 登录，DEMO-1 正向链路可跑通至 SIMULATED 部署，需求状态为 RELEASED。
  2. 缺少 PRD 评审、缺少 UX 即进入开发、Pipeline 失败却提交 QA 等九类负向场景全部被 Guard 或发布预检拒绝。
  3. PRD 历史版本只读不可改；并发保存出现版本冲突时提供差异处理，不发生静默覆盖。
  4. 合并 MR、部署未经人工审批不能执行；审批 30 分钟超时后任务进入待恢复，且不重复创建分支。
  5. Trace 可按时间顺序回放各 Agent 的工具调用；SSE 断线重连后事件不丢不重。
