# ADR-018：区分 Agent 代执行确认与 HIGH 风险审批

- 状态：Accepted
- 日期：2026-09-14

## 上下文

Agent Tool 的 `MEDIUM + ASK` 与 `HIGH` 都会暂停 Run，但两者表达的业务责任不同。MEDIUM 是用户确认
Agent 代自己执行本来已有权限执行的操作；HIGH 是职责分离审批。若统一禁止发起人决策，Product 用户连创建
Requirement 这类本职操作也必须交给他人批准，既不符合权限模型，也使单人确认流程无法完成。

## 决策

1. `MEDIUM + ASK` 是代执行确认。Run 发起人可凭 `agent.run` 确认或取消；恢复时仍重新校验原业务权限、
   冻结参数、资源版本和幂等键。
2. `HIGH` 是独立审批。发起人始终不得自批，决定者必须具有 `approval.decide`。
3. 非发起人决定 MEDIUM 请求时仍必须具有 `approval.decide`。
4. 确认卡片属于对话工作流，应在对话页面展示和操作；Run 轨迹保留为审计与故障诊断视图。

## 后果

- Product 用户可确认 Agent 代其创建 Requirement，但不能借此获得原本没有的业务权限。
- HIGH 部署等操作继续保持双人控制。
- 前端必须根据风险等级和 `requestedBy` 展示“确认执行”“取消”或“批准/拒绝”。

## 替代方案

- 所有风险等级均禁止自批：拒绝，因为把代执行确认误建模为职责分离审批。
- MEDIUM 默认无确认执行：保留为显式 `ALLOW` 策略，但不替代用户选择的 `ASK`。
