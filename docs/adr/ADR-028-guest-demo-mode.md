# ADR-028：游客模式共享演示账号

- 状态：Accepted
- 日期：2026-10-19
- 相关：ADR-021（领域管理员角色模型）、ADR-016（公司成员与账号审核）

## 上下文

面试官或试用者希望在不经过人工审核的前提下快速体验完整交付链路，但现有入口无法满足：自助注册
（`POST /api/v1/auth/register`）创建的账号固定为 `PENDING`，必须由全局管理员或 Owner 审核后方可登录；
四个领域管理员角色按 ADR-021 只能由全局管理员或 Owner 分配，明确不支持自助注册。逐个人工审核对试用场景
成本过高，且审核者需要提前持有成员治理权限。

因此需要一个受控的公开入口：一次点击即可获得可完整走通需求交付（含各领域审批）的演示身份。

## 决策

1. 新增公开端点 `POST /api/v1/auth/guest`，无需登录。仅当实例已完成初始化且配置项
   `forge.auth.guest-mode-enabled` 为 `true` 时可用；开关关闭或实例未初始化时按资源不存在（404）处理，
   不做账号创建。
2. 复用单一共享游客账号：固定规范化登录邮箱 `guest@forge.demo`、展示名“游客”。首次调用创建，之后每次
   调用复用同一账号（按 `users.normalized_email` 唯一键与 `ON DUPLICATE KEY UPDATE` 幂等收敛）。
3. 游客账号与其公司成员关系直接以 `ACTIVE` 状态创建，跳过人工审核；成员加入时间按首次创建补齐。
4. 游客账号固定持有四个基础角色 `PRODUCT`、`UX`、`DEVELOPER`、`QA` 与四个领域管理员角色
   `PRODUCT_ADMIN`、`UX_ADMIN`、`DEVELOPER_ADMIN`、`QA_ADMIN`；不含 `OWNER` 与全局 `ADMIN`，因此
   不获得成员治理与角色分配权限。角色集合复用 ADR-021 已定义的现有系统角色，不新增角色码。
5. 游客账号存储随机 BCrypt 摘要作为密码，无法用密码登录；只能通过游客端点建立会话。建立会话的过程与
   普通登录一致（轮换 Session ID、写入最小认证主体），因此 `/api/v1/me` 等已登录端点对游客同样有效。
6. 开关默认开启，生产环境可通过环境变量 `FORGE_GUEST_MODE_ENABLED=false` 关闭。前端登录页仅在
   `/api/v1/setup/status` 返回 `guestModeEnabled=true` 且实例已初始化时展示游客入口。

## 后果

- 认证与权限模型出现一个受控例外：在开关开启的实例上，任何匿名访问者都能获得带四个领域审批权限的
  `ACTIVE` 成员身份。该例外不改变现有登录、审核与授权路径，仅新增一条独立入口。
- 领域管理员角色被非管理员自动授予，突破 ADR-021 “领域管理员只能由全局管理员或 Owner 分配、不支持
  自助注册”的边界；该突破仅限本 ADR 定义的游客账号，其他分配路径不变。
- 游客为共享账号，多个使用者共用同一身份与同一份演示数据，彼此不隔离；重复进入不会重置已有业务数据。
- 游客账号无可用密码，绕过了登录限流与失败锁定路径；该路径按公开端点暴露，需按开关评估是否在生产启用。
- 前端需在登录页增加游客入口，并让 `SetupStatus` 透传 `guestModeEnabled`。

## 替代方案

- 复用现有人工审核注册流程：拒绝，无法满足“快速尝试”，且要求试用者先持有治理权限。
- 每次进入新建独立游客账号：拒绝，账号与成员数据随试用次数膨胀，且无法持续演示同一份数据。
- 授予游客全局 `ADMIN` 或 `OWNER`：拒绝，游客无需成员治理与角色分配权限，授予会扩大攻击面。
- 使用固定明文密码口令登录：拒绝，口令需要在试用者之间传播，弱于一次性入口且难以回收。
