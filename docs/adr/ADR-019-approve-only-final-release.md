# ADR-019：Agent 过程动作默认直执行，仅最终发布人工审批

- 状态：Accepted
- 日期：2026-09-14
- 取代：ADR-018 中“MEDIUM + ASK 作为常规代执行确认”的默认选择

## 上下文

ForgeAI 的目标是让工作者通过 Agent 连续完成固定交付流程。若创建 Requirement、文档、任务，以及提交或通过
产品评审、UX 评审等每个 MEDIUM 过程动作都暂停等待点击确认，Agent 只能生成待办，无法真正降低流程操作成本。

这些动作仍受当前用户权限、公司作用域、确定性状态机 Guard、JSON Schema、幂等键和审计约束。逐次点击并不
增加新的授权边界。最终发布会改变交付环境，仍需要职责分离与独立人工决策。

## 决策

1. 常规 Agent Run 的 `mediumConfirmation` 默认值改为 `ALLOW`。
2. 创建或更新需求、文档、任务、测试、缺陷、Release 草稿，以及提交或决定产品/UX/QA 阶段评审等 MEDIUM
   过程动作，在权限和确定性 Guard 通过后直接执行，不暂停 Run。
3. `deploy_release` 保持 HIGH，必须冻结 Tool、参数和资源版本，并由非发起人完成最终发布审批。
4. `DENY` 保留为禁止 Agent 写操作的显式安全策略；`ASK` 仅为已有 API 调用方的兼容策略，不再是产品常规入口。
5. 自动执行不削弱 `forge-server` 的权威校验、租户边界、幂等、审计和失败即停语义。

## 后果

- Agent 可以连续完成产品、UX、开发和 QA 的过程创建与阶段推进，用户不再逐步点击审批。
- Web 常规会话只在最终发布 HIGH Tool 返回 `WAITING_APPROVAL` 时展示审批交互。
- 老调用方若显式传入 `ASK`，仍可暂时使用旧确认链路；后续移除该兼容能力需要单独的契约迁移。

## 替代方案

- 删除整个审批子系统：拒绝，因为最终发布仍需要职责分离、参数冻结与审计。
- 将所有 MEDIUM Tool 改成 LOW：拒绝，因为风险元数据仍需表达写副作用，并支持显式 `DENY` 策略。
